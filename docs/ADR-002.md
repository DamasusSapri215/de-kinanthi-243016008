ADR-002: Pemilihan format Parquet untuk data analitik 
Status     : diusulkan 
Konteks    : 
Sistem analitik memerlukan format penyimpanan yang efisien untuk membaca data (read data) dalam jumlah besar. Format yang dipilih harus mendukung pemrosesan data, efisiensi penyimpanan dan dapat digunakan dalam berbagai alat analitik.
Opsi       : A, B, C beserta trade-off (biaya, latensi, kompleksitas) 
a. CSV, mudah dibaca oleh manusia dan mendukung banyak alat, tetapi kurang efisien untuk penyimpanan dan pembacaan data analitik yang berukuran besar.
b. Parquet, mendukung dalam penyimpanan kolumnar, kompresi yang efisien dan biaya lebih rendah , tetapi membutuhkan alat yang mendukung format tersebut.
c. Format tertutup milik vendor. Dapat integrasi dengan layanan tertentu, tetapi risiko menimbulkan ketergantungan pada vendor bahkan mengeluarkan biaya lagi.
Keputusan  : 
Memilih Parquet sebagai format penyimpanan data analitik, karena penyimpanan kolumdar dan kompresinya dapat meningkatkan efisiensi penyimpanan dalam pembacaan data dalam kebutuhan analitik.
Tipe       : two-way 
Konsekuensi: dampak, risiko, dan exit plan 
Dampak:
- Penyimpanan data analitik berpotensi lebih efisien
Risiko
- Pemrosesan data hanya bisa digunakan untuk mendukung parquet. 
- Konversi format tetap membutuhkan waktu dan sumber daya.
- Struktur skema dan kompatibilitas perlu diuji ketika data digunakan oleh alat yang berbeda.
exit plain:
Simpan dokumen skema, ujo kompatibilitas untu data analitik, dan mempertahankan proses ekspor atau konversi ke csv atau format lain apabila diperlukan.
